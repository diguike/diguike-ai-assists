# 原理动画（科技原理、产品拆解、流程讲解）

讲一个东西是怎么工作的：一台机器、一段代码、一条流水线。横屏，Edge TTS 口播，3～6 分钟。

和「讲解」片种的区别在画面组织：讲解片是一页页 PPT，说一句出一个元素；原理动画是**几个连续的场景**。每个场景是一块大画布，镜头在上面移动；**同一个东西一直在画面上，被拆开、变形、流动**，不会被下一页替换掉。

- 模板：`studio new <名字> '标题' --kind mechanism`。默认风格「瓷光」`ciguang`：瓷白底、钴蓝信号色、细黑字。模板本身就是一个能跑的场景例子，先读它。
- 画图部件：`engine/kit.py`，有卡片、代码窗、波形、点阵网格、柔光。
- 动起来：`s.animate()`，接口见 `references/atoms.md`「连续动画（场景）」。

## 什么时候用

- 用户要「科技原理的动画拆解」「像 Kurzgesagt / Apple 产品原理那样」，或者明确说不要 PPT 感。
- 内容本身有「东西在变」：信号流过去、零件拆开、一段声音被切开再拼起来、数字从一处流到另一处。
- 只是一串观点或清单时，用讲解片种，不要硬做成原理动画。

## 流程

### 1. 先写「东西清单」，再写稿

列出片子里有哪些**一直存在的东西**，比如代码窗、模型、波形、时间轴、浏览器。再列每个东西经历的**状态变化**，比如出现 → 被切开 → 送进模型 → 变成波形 → 被打上时间。

一个场景最好只围着一两个东西转。东西没有变化的段落，就不要放进原理动画。

### 2. 分场景写稿

一个场景对应一段完整的因果，30～80 秒，5～12 句。

每句口播指向一个**动作**，不指向一个元素：「把每一帧摆好再截图」对应帧卡片从浏览器里飞出来，不对应「出现一张卡片」。

数字照样从 `data/*.json` 读，场景 JS 里的数字也要从 Python 传进去，不在 JS 里手填（核查会查）。

### 3. 画静态，再写动作

- **静态**写在 `episode.py`：用 `kit` 画好所有东西的**最终状态**，id 起得有意义。每个场景外面包一层世界容器 `<div id="aN-w" style="width:…;height:…">`，镜头就移动这一层。
- **动作**写在 `scenes/<场景>.js`（或直接写进 `s.animate('''…''')`），用法见 atoms.md：
  - 时刻用 `S.word('b3', '配音', -.2)` 卡在说到某个词的那一刻；
  - 镜头用 `S.cam(world, [[时刻, x, y, 倍数, 时长], …])`；
  - 出现用 `S.soft()`，描线用 `S.stroke()`，沿路径走用 `S.along()`，形变用 `S.morph()` / `S.lerp()`。
- 静态图（`stills`）显示的就是场景的最终状态，也是封面素材。

### 4. 音效

场景里的动作没有注册元素，**不会自动配音效**。动画开始和结束要配小音效，所以在关键动作上加 `s.sound('b2', 'tone', word='出现')`：
- 卡片落定用 `tone` / `pop`；
- 线和流动用 `swish`（`d=` 时长）；
- 计数和切点用 `tick`；
- 结论用 `chime`。

一个场景 5～10 个就够了，宁少勿多。

### 5. 先看再出

```bash
studio <名字> silent s02        # 无声动画，按估计时长，几分钟
studio <名字> check             # 配音 + 多音字 + 时间轴 + 静态图 + 节奏
studio <名字> preview s02       # 带声音只看一个场景
studio <名字> all
```

每改一个场景，就用 `silent <场景>` 出片，再用 ffmpeg 抽 6～9 帧拼成图来看，一轮几分钟。场景页每一帧都要截图，整片渲染比讲解片慢（3.5 分钟约 10 分钟，Windows 笔记本上可能更久）。

## 硬规则

- **不要翻页式**：一个场景里的东西不被替换，只被移动、拆开、变形。换场景用 `('through', 元素)` 推进上一场景的某个东西里，或者慢溶解。
- **说到哪，动到哪**：动作卡在 `S.word()` 上，不卡在整句开头。画面比口播早出来 1 秒以上，观众会去看还没讲到的东西。
- **镜头有目的**：推近是为了看清一个细节，拉远是为了看关系。一个场景里镜头移动 2～4 次，每次 1.8～2.4 秒，最后停稳。
- **每个场景都要有停住的时刻**：结论出来以后让画面稳住 1～2 秒。粒子和波形的微动可以留着，主体别再动。
- **示意动画要符合真实规则**：画出来的流程要和真实的做法一致，核查会查。
- **配色克制**：七到八成是中性色（瓷白、墨黑、灰），钴蓝表示信息和信号，珊瑚色表示声音和注意，青绿表示通过。一个画面里强调色不超过两种。
- **做精致，不做粗线条**：
  - 卡片圆角 16px 以内，加 1px 细描边，阴影要淡；
  - 描线 2px 以内；
  - 示意图用细线和浅色底，不用大块纯色；
  - 颜色写主题变量，不写死色值。

## 经验（每做完一条，把用户反馈和踩到的坑记在这里）

- 这个片种的由来：主题系统只换颜色、字体和入场方式，版式和「一页页出元素」的结构不变，所以怎么换风格都像 PPT。用户嫌"像 PPT""不够丝滑"时，要换的是片种，不是配色。
- 好用的场景做法（细节见 atoms.md「配方」）：代码长出三层再合成一帧（CSS 3D 爆炸图）；一句代码分成配音和字幕两条带子；放大镜扫过旧说法，划掉，换成正确的；同一排波形从一种状态变成另一种；帧卡片从浏览器里出来，相同的叠成一摞。
- 背景别灰暗沉闷，元素别粗：用暖白底、细描边小圆角卡片、细线条；示意图里的纯色方块和圆饼换成细线面积图和圆环。
- 踩到的坑：
  - **标签引线**接在 3D 平面的哪个点，用平面里放的 0×0 锚点元素，然后 `getBoundingClientRect()` 量出来。不要用平面的包围盒去猜角点。
  - **文字居中**别用 `transform: translateX(-50%)`，场景的 `S.set()` 会覆盖 transform。用 `kit.text(center=True)`。
  - **底部标题和字幕**会撞在一起：最后落版的标题放在画面 3/4 高度以上。
  - **一句文字变成飞走的胶囊**时，胶囊的字要和原文逐像素对齐（位置减掉 padding），否则先出现一个重影。
  - 渲染完看一遍有没有新的重叠：说明文字容易压在动起来以后的卡片堆上。
